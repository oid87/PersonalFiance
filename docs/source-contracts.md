# Data source contracts

`scripts/source_manifest.json` lists every `fetch_`, `prep_`, and `compute_` source, its output paths, cadence of invocation, routes, explicit dependencies, and per-output validation profile. `scripts/check_pipeline.py` compares that list with the real US/TW/forward P/E workflows and local shell entry. Adding a source without wiring and a contract fails the check. Route dependency order is checked where both scripts run in the same route. A source consumed from already committed data in the other route is not treated as an ordering edge.

Profiles are based on the current source code and payloads. `ohlcv` requires ISO dates, unique ascending dates, and finite non-null open/high/low/close/volume. `dated_rows` requires ISO dates on every row, source-specific typed composite keys where relevant, and finite values for observed numeric fields when present; optional numeric fields may be null. Contracted dated arrays must be nonempty unless `allow_empty` is explicitly set. `heterogeneous_object` preserves source-specific nested structures and checks JSON syntax and finite numeric values. Every root file also has a conflict-marker and catastrophic-shrink guard. Snapshot and archive paths use the existing strict macro archive validator. The independently scheduled forward P/E JSONL validates each line, ascending unique execution dates and price-as-of dates, required fields, finite values, source-weight coverage, constituent counts, valid flags, and chart label/point agreement.

`source_contracts.py` expands the manifest's `data/{stock_stem}.json` template from the literal `TICKERS` mapping in `fetch_stocks.py` using AST; it never imports or runs the fetcher. The current mapping names 41 stock/index files, each with an `ohlcv` contract by filename. An unknown JSON file is not inferred to be a stock from its first row. The default full-directory validator requires all 41 files, rejects an absent or empty data directory, and reports any root JSON that existed in `--baseline-dir` but disappeared. Other sources are not silently made required when their producer has an optional route.

Use `python3 scripts/validate_data.py --no-shrink` for the complete local data directory. Synthetic or intentionally partial fixtures must pass `--allow-partial`; this only relaxes missing-stock checks, and existing known filenames still receive their full schema validation. Empty or nonexistent fixture directories still fail. `--baseline-dir PATH` detects deleted root files in either mode. `scripts/check_pipeline.py` uses the same contract expansion to detect a broken stock template or unsafe/nonliteral ticker mapping.

The forward P/E script defines coverage as the sum of *input holding weights used*, with no renormalization. Scraped percentages may total slightly more than 100%; current QQQ records reach 1.0005. The validator allows 1.01 as a source-weight tolerance and still requires at least 0.95 for any record marked valid. This is not an assertion that coverage is a normalized probability.

`fetch_margin_ratio_mm.py` is a manual research source and remains outside production schedules. `fetch_forward_pe.py` runs twice in its independent workflow (VOO and QQQ) and is excluded from local refresh. `fetch_us_macro_diagnostic.py` runs through the US macro shell pipeline in CI. No source unit was inferred from a file name: the manifest records unit metadata only where the source/payload documents it (US margin debt in USD millions and Taiwan margin balance in 億元). The manual margin-ratio series has a documented unresolved gap from the external M 平方 display; validation does not claim the series matches that vendor.
